# Мы на % — ежедневный ритуал для пары

Один вопрос в день на двоих. Утром каждый отвечает за себя и угадывает половинку, вечером (или как только ответили оба) — раскрытие. PWA, работает в России без VPN: никаких внешних сервисов, шрифтов и CDN.

План, модель данных и этапы — в [docs/PLAN.md](docs/PLAN.md).

## Запуск локально

Нужен Node.js 22.13+.

```bash
npm install
npm run dev
```

- клиент: http://localhost:5173 (Vite, с прокси на API)
- сервер: http://localhost:8787 (Fastify + SQLite, база в `./data/polovinka.db`)

## Проверка с двух телефонов (этапы 1–3)

1. Ноутбук и оба телефона в одном Wi-Fi. Узнайте IP ноутбука (`ip a` / `ipconfig`).
2. `npm run dev` — Vite уже слушает все интерфейсы.
3. Телефон 1 открывает `http://<ip>:5173`, вводит имя, отвечает на вопрос.
4. «Позвать половинку» → по http Web Share недоступен, сработает «Скопировать ссылку».
   Отправьте ссылку себе любым способом и откройте на телефоне 2.
5. Телефон 2 вводит имя — пара создана, на телефоне 1 появляется имя партнёра без перезагрузки (SSE).
6. Телефон 2 отвечает — у обоих раскрытие с анимацией, затем «Почему?» и «Тема на вечер».
7. Вкладка «Жест» — отправьте тёплый жест, он придёт карточкой на другой телефон.

Ссылка приглашения берёт хост из адреса, по которому открыт сайт, поэтому с телефона 2 она откроется по тому же `http://<ip>:5173`.

## Боевой запуск (VPS, HTTPS)

```bash
export DOMAIN=example.ru
docker compose up -d --build
```

Caddy сам получит сертификат. HTTPS нужен для PWA, Web Share, push и «Добавить на экран».

Переменные окружения сервера:

| Переменная  | Значение по умолчанию | Назначение                                  |
|-------------|-----------------------|---------------------------------------------|
| `PORT`      | `8787`                | порт                                        |
| `DATA_DIR`  | `./data`              | каталог с SQLite                            |
| `PUBLIC_URL`| из заголовков запроса | адрес для ссылок приглашений и OG           |
| `STATS_KEY` | пусто                 | ключ к странице `/stats`; пустой ключ выключает её |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | генерируются в `DATA_DIR/vapid.json` | ключи web push; задайте явно, если переносите сервер |
| `VAPID_SUBJECT` | `mailto:hello@polovinka.local` | контакт для push-сервисов браузеров |
| `WEB_DIST`  | `web/dist`            | каталог собранного клиента                  |

## Проверка этапа 4 (нужен HTTPS)

Service worker, push и «Добавить на экран» работают только по HTTPS (или на `localhost`). Поднимите приложение на VPS через `docker compose`, затем:

1. Откройте сайт на телефоне, ответьте на вопрос. После раскрытия появится карточка «На экран „Домой“». На iPhone это делается через «Поделиться» в Safari, и push там работает только у добавленного на экран приложения.
2. Настройки → «Уведомления» → «Включить на этом телефоне», разрешите уведомления. Выставьте утреннее время на ближайшую минуту и закройте приложение: придёт «Вопрос дня ждёт». Вечернее уведомление о раскрытии приходит сразу, как ответили оба, если приложение закрыто. Не больше двух в день.
3. Включите авиарежим, ответьте на вопрос: появится «Нет сети. Ответ сохранён на телефоне». Закройте приложение, выключите авиарежим, откройте: ответ ушёл, у партнёра раскрытие. Перезапуск офлайн показывает оболочку и последний вопрос из кэша.
4. Статистика: `https://домен/stats`, ключ из `STATS_KEY`.

Push в Chrome доставляется через сервис Google, в Firefox через Mozilla, на iOS через Apple. Наш сервер к ним обращается с VPS, но из России доставка на телефон не гарантирована, поэтому основной канал в приложении это SSE, а «Позвать» идёт через мессенджер.

## Структура

```
shared/   типы API и банк вопросов (shared/questions.json, 269 вопросов)
server/   Fastify + node:sqlite, раздаёт /api и web/dist
web/      React + Vite + Tailwind, PWA
```

Проверка банка вопросов: `npm run check:questions`. Service worker собирается из `web/sw-template.js` при сборке.
