# Деплой на Timeweb Cloud — пошагово

Нужен **облачный сервер (VPS)** в Timeweb Cloud, а не виртуальный хостинг:
приложение — процесс Node.js с базой SQLite на диске. Всё остальное делает
скрипт `deploy/install.sh` одной командой.

Названия кнопок в панели Timeweb иногда меняются. Если что-то называется
чуть иначе, ищите по смыслу.

## Шаг 1. Создать сервер

1. Зайдите на timeweb.cloud и войдите в панель.
2. В левом меню откройте **«Облачные серверы»** и нажмите **«Создать»**.
3. **Операционная система:** вкладка с ОС → **Ubuntu 24.04** (подойдёт и 22.04).
   Вкладку «Маркетплейс» можно не трогать: Docker поставит скрипт.
4. **Регион:** Москва или Санкт-Петербург, ближе к вам и к партнёру.
5. **Конфигурация:** самая простая с 1 CPU. Лучше 2 ГБ памяти; на 1 ГБ тоже
   заработает, скрипт сам добавит swap для сборки. Диска хватит минимального.
6. **SSH-ключ:** можно пропустить, войдём по паролю.
7. **Имя сервера:** например, `polovinka`. Нажмите **«Заказать»** / **«Создать»**.
8. Через 1–2 минуты сервер запустится. На вкладке **«Дашборд»** сервера
   скопируйте **IP-адрес** и **root-пароль**.

## Шаг 2. Домен (можно позже)

Без домена можно проверить всё на бесплатном адресе вида
`203-0-113-7.sslip.io` (ваш IP через дефисы): скрипт предложит его сам.
Для постоянной работы лучше свой домен.

**Если домен в Timeweb:** **«Домены и SSL»** → **«Мои домены»** → кликните по
домену → вкладка **«Редактор DNS»** (или «DNS») → **«Добавить запись»** →
тип **A**, имя `@` (сам домен), значение — **IP сервера** → **«Сохранить»**.
Для адреса с `www` добавьте вторую A-запись с именем `www` и тем же IP.
Если старая A-запись уже есть, отредактируйте её вместо создания новой.

**Если домен у другого регистратора:** то же самое в его панели DNS.
Если у домена сторонние NS-серверы, запись делается там, где эти NS.

Запись расходится от 5 минут до нескольких часов. Сертификат HTTPS выпускать
не нужно: его получит Caddy автоматически, как только домен начнёт указывать
на сервер.

## Шаг 3. Подключиться к серверу

**С компьютера (удобнее, работает вставка):**

- Windows 10/11: Пуск → наберите **«Терминал»** или **«PowerShell»** → откройте.
- macOS: Launchpad → **«Терминал»**.

Введите (вместо IP — ваш):

```
ssh root@203.0.113.7
```

На вопрос `Are you sure you want to continue connecting` напишите `yes` и Enter.
Затем вставьте root-пароль (в Windows — правой кнопкой мыши, в macOS — Cmd+V)
и нажмите Enter. Пароль при вводе не отображается, это нормально.

**Без компьютера:** в панели Timeweb на странице сервера вкладка **«Консоль»**.
Логин `root`, пароль с «Дашборда». Вставка там работает не всегда, тогда
команду придётся набрать вручную.

## Шаг 4. Одна команда

Скопируйте целиком и вставьте в терминал сервера:

```
curl -fsSL https://raw.githubusercontent.com/PChebyshev/Polovinka/claude/plan-and-data-model/deploy/install.sh | bash
```

Скрипт:

1. добавит swap, если памяти меньше 2 ГБ;
2. поставит Docker из репозитория Ubuntu;
3. подключит зеркало Docker Hub от Timeweb (`dockerhub.timeweb.cloud`),
   потому что с российских IP Docker Hub бывает недоступен;
4. скачает код в `/opt/polovinka`;
5. спросит **домен** (Enter — взять `sslip.io`) и **почту** для push-сервисов;
6. сам придумает ключ к странице статистики;
7. соберёт и запустит приложение. Первый раз 3–8 минут.

В конце он напечатает адрес сайта и ключ статистики. **Сохраните ключ.**

## Шаг 5. Проверить

1. Откройте `https://ваш-домен` на телефоне. Если браузер ругается на
   сертификат, подождите пару минут: Caddy его ещё получает.
2. Введите имя, нажмите «Позвать половинку», отправьте ссылку партнёру.
3. Ответьте оба — будет раскрытие.
4. На телефоне лендинг первым шагом предлагает добавить Половинку на экран
   «Домой». Иконка открывается сразу в нужном месте, в том числе по ссылке-приглашению.
   Если начали в браузере, на главной есть «Установить на экран»: иконка войдёт
   в тот же аккаунт сама. Подробно — docs/CJM.md.
5. В приложении с экрана: Настройки → «Уведомления» → «Включить на этом
   телефоне», затем «Проверить уведомление».
6. Статистика: `https://ваш-домен/stats`, ключ из шага 4.

## Обновить после новых изменений

```
ssh root@IP
bash /opt/polovinka/deploy/install.sh
```

Настройки и все данные сохраняются.

## Если что-то пошло не так

```
cd /opt/polovinka
docker compose ps              # оба сервиса должны быть Up
docker compose logs -f caddy   # ошибки сертификата
docker compose logs -f app     # ошибки приложения
```

- **Сертификат не выпускается.** Проверьте, что домен указывает на IP сервера:
  `getent hosts ваш-домен`. Если включали «Firewall» в панели Timeweb,
  разрешите входящие TCP 80 и 443.
- **Сменить домен** (например, с `sslip.io` на свой). Сначала A-запись домена
  должна указывать на IP сервера, потом одна команда:
  ```
  curl -fsSL https://raw.githubusercontent.com/PChebyshev/Polovinka/claude/plan-and-data-model/deploy/install.sh | DOMAIN=mydomain.ru bash
  ```
  Ключ статистики и почта сохранятся. `www.mydomain.ru` будет переадресовывать
  на `mydomain.ru`, если для `www` тоже есть A-запись. Вход в приложении привязан
  к адресу сайта: после смены домена на телефонах нужно войти заново и заново
  добавить иконку на экран.
- **Сборка упала на загрузке образов.** Зеркало недоступно — допишите другое
  в `/etc/docker/daemon.json` (например, `https://dockerhub1.beget.com`),
  выполните `systemctl restart docker` и запустите скрипт ещё раз.

## Бэкап

Все данные (база, ключи push, картинки недели) — в томе Docker `app-data`:

```
docker run --rm -v polovinka_app-data:/data -v /root:/backup alpine \
  tar czf /backup/polovinka-$(date +%F).tgz -C /data .
```

Архив появится в `/root`. Скачать на компьютер:
`scp root@IP:/root/polovinka-*.tgz .`

Также можно включить автоматические бэкапы всего сервера в панели Timeweb
на странице сервера.

## Переменные в `/opt/polovinka/.env`

| Переменная | Назначение |
|---|---|
| `DOMAIN` | домен для сертификата и ссылок |
| `STATS_KEY` | ключ страницы `/stats` |
| `VAPID_EMAIL` | контакт для push-сервисов |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | необязательно; задайте при переезде на другой сервер, чтобы не потерять push-подписки |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | необязательно; включают привязку почты и вход по коду из письма |

## Вход по почте (необязательно)

Без SMTP приложение работает полностью, просто в настройках нет пункта «Почта»,
а на экране входа — ссылки «Войти по почте». Код восстановления работает всегда.

Чтобы включить, добавьте в `/opt/polovinka/.env` пять строк и перезапустите:

```
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USER=polovinka@yandex.ru
SMTP_PASS=пароль-приложения
SMTP_FROM=polovinka@yandex.ru
```

```
cd /opt/polovinka && docker compose up -d
```

Где взять пароль:

- **Яндекс** — заведите отдельный ящик для приложения. В id.yandex.ru → Безопасность →
  «Пароли приложений» создайте пароль для «Почты» и используйте его как `SMTP_PASS`.
  Обычный пароль от ящика не подойдёт. Сервер `smtp.yandex.ru`, порт `465`.
- **Mail.ru** — Настройки → Безопасность → «Пароли для внешних приложений».
  Сервер `smtp.mail.ru`, порт `465`.

Проверить, что письма уходят: `docker compose logs app | grep почта` — должно быть
«SMTP … готов». Письмо содержит только шестизначный код, никаких рассылок.
