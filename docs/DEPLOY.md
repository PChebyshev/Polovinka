# Деплой на Timeweb Cloud — пошагово

Нужен **облачный сервер (VPS)** в Timeweb Cloud, а не виртуальный хостинг:
приложение — процесс Node.js с базой SQLite на диске. Всё остальное делает
скрипт `deploy/install.sh` одной командой.

Названия кнопок в панели Timeweb иногда меняются. Если что-то называется
чуть иначе, ищите по смыслу.

## Шаг 1. Создать сервер

1. Зайдите на timeweb.cloud и войдите в панель.
2. В левом меню откройте **«Облачные серверы»** и нажмите **«Создать»**.
3. **Операционная система:** вкладка с ОС → **Ubuntu 24.04** (подойдёт и 22.04).
   Вкладку «Маркетплейс» можно не трогать: Docker поставит скрипт.
4. **Регион:** Москва или Санкт-Петербург, ближе к вам и к партнёру.
5. **Конфигурация:** самая простая с 1 CPU. Лучше 2 ГБ памяти; на 1 ГБ тоже
   заработает, скрипт сам добавит swap для сборки. Диска хватит минимального.
6. **SSH-ключ:** можно пропустить, войдём по паролю.
7. **Имя сервера:** например, `polovinka`. Нажмите **«Заказать»** / **«Создать»**.
8. Через 1–2 минуты сервер запустится. На вкладке **«Дашборд»** сервера
   скопируйте **IP-адрес** и **root-пароль**.

## Шаг 2. Домен (можно позже)

Без домена можно проверить всё на бесплатном адресе вида
`203-0-113-7.sslip.io` (ваш IP через дефисы): скрипт предложит его сам.
Для постоянной работы лучше свой домен.

**Если домен в Timeweb:** **«Домены и SSL»** → **«Мои домены»** → кликните по
домену → вкладка **«Редактор DNS»** (или «DNS») → **«Добавить запись»** →
тип **A**, имя `@` (сам домен), значение — **IP сервера** → **«Сохранить»**.
Для адреса с `www` добавьте вторую A-запись с именем `www` и тем же IP.
Если старая A-запись уже есть, отредактируйте её вместо создания новой.

**Если домен у другого регистратора:** то же самое в его панели DNS.
Если у домена сторонние NS-серверы, запись делается там, где эти NS.

Запись расходится от 5 минут до нескольких часов. Сертификат HTTPS выпускать
не нужно: его получит Caddy автоматически, как только домен начнёт указывать
на сервер.

## Шаг 3. Подключиться к серверу

**С компьютера (удобнее, работает вставка):**

- Windows 10/11: Пуск → наберите **«Терминал»** или **«PowerShell»** → откройте.
- macOS: Launchpad → **«Терминал»**.

Введите (вместо IP — ваш):

```
ssh root@203.0.113.7
```

На вопрос `Are you sure you want to continue connecting` напишите `yes` и Enter.
Затем вставьте root-пароль (в Windows — правой кнопкой мыши, в macOS — Cmd+V)
и нажмите Enter. Пароль при вводе не отображается, это нормально.

**Без компьютера:** в панели Timeweb на странице сервера вкладка **«Консоль»**.
Логин `root`, пароль с «Дашборда». Вставка там работает не всегда, тогда
команду придётся набрать вручную.

## Шаг 4. Одна команда

Скопируйте целиком и вставьте в терминал сервера:

```
curl -fsSL https://raw.githubusercontent.com/PChebyshev/Polovinka/claude/plan-and-data-model/deploy/install.sh | bash
```

Скрипт:

1. добавит swap, если памяти меньше 2 ГБ;
2. поставит Docker из репозитория Ubuntu;
3. подключит зеркало Docker Hub от Timeweb (`dockerhub.timeweb.cloud`),
   потому что с российских IP Docker Hub бывает недоступен;
4. скачает код в `/opt/polovinka`;
5. спросит **домен** (Enter — взять `sslip.io`) и **почту** для push-сервисов;
6. сам придумает ключ к странице статистики;
7. соберёт и запустит приложение. Первый раз 3–8 минут.

В конце он напечатает адрес сайта и ключ статистики. **Сохраните ключ.**

## Шаг 5. Проверить

1. Откройте `https://ваш-домен` на телефоне. Если браузер ругается на
   сертификат, подождите пару минут: Caddy его ещё получает.
2. Введите имя, нажмите «Позвать половинку», отправьте ссылку партнёру.
3. Ответьте оба — будет раскрытие.
4. На телефоне лендинг первым шагом предлагает добавить Половинку на экран
   «Домой». Иконка открывается сразу в нужном месте, в том числе по ссылке-приглашению.
   Если начали в браузере, на главной есть «Установить на экран»: иконка войдёт
   в тот же аккаунт сама. Подробно — docs/CJM.md.
5. В приложении с экрана: Настройки → «Уведомления» → «Включить на этом
   телефоне», затем «Проверить уведомление».
6. Статистика: `https://ваш-домен/stats`, ключ из шага 4.

## Обновить после новых изменений

```
ssh root@IP
bash /opt/polovinka/deploy/install.sh
```

Настройки и все данные сохраняются.

## Если что-то пошло не так

```
cd /opt/polovinka
docker compose ps              # оба сервиса должны быть Up
docker compose logs -f caddy   # ошибки сертификата
docker compose logs -f app     # ошибки приложения
```

- **Сертификат не выпускается.** Проверьте, что домен указывает на IP сервера:
  `getent hosts ваш-домен`. Если включали «Firewall» в панели Timeweb,
  разрешите входящие TCP 80 и 443.
- **Сменить домен** (например, с `sslip.io` на свой). Сначала A-запись домена
  должна указывать на IP сервера, потом одна команда:
  ```
  curl -fsSL https://raw.githubusercontent.com/PChebyshev/Polovinka/claude/plan-and-data-model/deploy/install.sh | DOMAIN=mydomain.ru bash
  ```
  Ключ статистики и почта сохранятся. `www.mydomain.ru` будет переадресовывать
  на `mydomain.ru`, если для `www` тоже есть A-запись. Вход в приложении привязан
  к адресу сайта: после смены домена на телефонах нужно войти заново и заново
  добавить иконку на экран.
- **Сборка упала на загрузке образов.** Зеркало недоступно — допишите другое
  в `/etc/docker/daemon.json` (например, `https://dockerhub1.beget.com`),
  выполните `systemctl restart docker` и запустите скрипт ещё раз.

## Бэкап

### Автоматически: копия базы в облачное хранилище

Раз в сутки около 04:00 МСК приложение делает снимок базы, сжимает, шифрует паролем
`BACKUP_PASSWORD` (AES-256) и отправляет в S3-совместимое хранилище — Yandex Object Storage
или Timeweb S3. Без пароля копию не прочитать ни хранилищу, ни тому, кто получит ключи.
Состояние видно вверху `/stats`: «✓ Резервная копия: …» или причина ошибки.

Что настроить в Yandex Cloud (console.yandex.cloud):

1. **Object Storage → Создать бакет.** Имя уникальное, например `polovinka-backup-7k3`;
   доступ на чтение объектов и к списку — «Ограниченный»; класс — «Стандартное».
2. **Сервисные аккаунты → Создать.** Имя `polovinka-backup`, роли `storage.uploader`
   и `storage.viewer`.
3. Откройте аккаунт → **Создать новый ключ → Создать статический ключ доступа.**
   Скопируйте «Идентификатор ключа» и «Секретный ключ» — секрет показывают один раз.
4. Необязательно: в бакете **Жизненный цикл → Добавить правило**, префикс `backups/`,
   удалять через 90 дней.

Добавьте в `/opt/polovinka/.env` и запустите `bash /opt/polovinka/deploy/install.sh`:

```
BACKUP_S3_BUCKET=polovinka-backup-7k3
BACKUP_S3_KEY_ID=идентификатор-ключа
BACKUP_S3_SECRET=секретный-ключ
BACKUP_PASSWORD=длинная-фраза-которую-вы-придумали
```

Для Timeweb S3 добавьте ещё `BACKUP_S3_ENDPOINT=https://s3.timeweb.cloud` и `BACKUP_S3_REGION=ru-1`.

**Сохраните `BACKUP_PASSWORD` и ключи вне сервера** (менеджер паролей, заметки):
если сервер пропадёт, вместе с ним пропадёт и `.env`, а без пароля копии бесполезны.

Проверить сразу, не дожидаясь ночи:

```
cd /opt/polovinka
docker compose exec app node server/dist/server/src/backup.js now
docker compose exec app node server/dist/server/src/backup.js list
```

### Восстановление из копии

```
cd /opt/polovinka
docker compose exec app node server/dist/server/src/backup.js list
docker compose exec app node server/dist/server/src/backup.js restore polovinka-ГГГГММДД-ЧЧММ.db.gz.enc /data/restored.db
docker compose stop app
docker run --rm -v polovinka_app-data:/data alpine sh -c \
  'cd /data && mkdir -p before-restore && cp polovinka.db* before-restore/ && mv restored.db polovinka.db && rm -f polovinka.db-wal polovinka.db-shm'
docker compose start app
```

Текущая база перед заменой сохраняется в `before-restore/`. На новом сервере: сначала
`install.sh` с тем же `.env` (те же `BACKUP_*`), потом эти команды.

### Вручную: архив всего тома

База, ключи push и картинки недели лежат в томе Docker `app-data`:

```
docker run --rm -v polovinka_app-data:/data -v /root:/backup alpine \
  tar czf /backup/polovinka-$(date +%F).tgz -C /data .
```

Архив появится в `/root`. Скачать на компьютер:
`scp root@IP:/root/polovinka-*.tgz .`

## Зарубежный вход для людей с VPN

VPN с выходом за границу (AdGuard VPN и подобные) не доносит трафик до российского
сервера: на входе в Россию его режут для известных VPN-сетей. При этом из обычного
зарубежного дата-центра сервер доступен. Поэтому ставим второй маленький сервер за
границей (Timeweb: Казахстан, Нидерланды, Польша — оплата в рублях), который только
пересылает запросы в Москву. Данные остаются на основном сервере.

1. Создайте сервер (минимальный тариф, Ubuntu). В DNS домена добавьте A-запись
   `go` → IP нового сервера (получится `go.polovinka.online`).
2. На новом сервере:
   ```
   curl -fsSL https://raw.githubusercontent.com/PChebyshev/Polovinka/claude/plan-and-data-model/deploy/edge-install.sh | EDGE_DOMAIN=go.polovinka.online bash
   ```
3. На основном сервере допишите в `/opt/polovinka/.env` строку `EDGE_HOSTS=go.polovinka.online`
   и запустите `bash /opt/polovinka/deploy/install.sh`. После этого ссылки-приглашения,
   карточки и OG у людей, пришедших через вход, строятся с доменом входа.
4. Проверка: `https://go.polovinka.online/api/health` → `{"ok":true}`.

В рекламе для Telegram давайте ссылки на `go.polovinka.online` — в `/stats` → «Реклама»
у каждой кампании видно, сколько переходов пришло через вход (это и есть люди с VPN).
Обычные пользователи продолжают пользоваться `polovinka.online`. Вход и основной сайт —
разные адреса, поэтому вход на одном не действует на другом: это нормально, человек
живёт там, где установил приложение.

**Запасной вход для уже установленного приложения.** Если человек поставил Половинку с
`polovinka.online`, а потом включил VPN, приложение откроется с кэша, а запросы к API,
которые не дошли до основного сервера, само отправит через `go.polovinka.online` (один
раз за сессию проверяет `/api/net/ping`; имя входа зашито в `shared/src/text.ts`,
`EDGE_FALLBACK_HOST`). Для этого вход отдаёт CORS-заголовки для основного домена —
конфиг в `deploy/edge/Caddyfile`; после его изменения на сервере входа повторно
запустите команду из шага 2. В `/stats` такие переключения видны как событие
`edge_fallback`. Переадресацию с основного домена на вход сделать нельзя: при
недоступности сервера запрос до него просто не доходит, отвечать некому.

## Переменные в `/opt/polovinka/.env`

| Переменная | Назначение |
|---|---|
| `DOMAIN` | домен для сертификата и ссылок |
| `STATS_KEY` | ключ страницы `/stats` |
| `VAPID_EMAIL` | контакт для push-сервисов |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | необязательно; задайте при переезде на другой сервер, чтобы не потерять push-подписки |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | включают привязку почты и вход по коду из письма |
| `BACKUP_S3_BUCKET`, `BACKUP_S3_KEY_ID`, `BACKUP_S3_SECRET`, `BACKUP_PASSWORD` | ежедневная зашифрованная копия базы в хранилище; `BACKUP_S3_ENDPOINT`, `BACKUP_S3_REGION` — если не Яндекс |
| `EDGE_HOSTS` | домены зарубежных входов через запятую (см. раздел выше) |
| `EMAIL_REQUIRED` | `1` (по умолчанию) — просить почту после первого ответа; `0` — не просить |
| `DATA_LOCATION`, `OPERATOR_NAME`, `PRIVACY_CONTACT` | необязательно; показываются на странице «Что мы храним», см. `docs/LEGAL.md` |
| `CROWD_MIN` | с какого числа ответов показывать «Как ответили другие пары», по умолчанию 20 |
| `AI_PROVIDER` и ключи | необязательно; персональные идеи, подсказки заботы и «вопрос по вашим ответам», см. ниже |

## ИИ для рекомендаций (необязательно)

Без ИИ всё работает: идеи после ответов берутся из заранее написанных,
подсказки заботы — по шаблону, а кнопки «Вопрос по вашим ответам» нет.
С ИИ идеи и подсказки становятся персональными, и появляется вопрос,
составленный по истории ответов пары (один в день).

Два варианта — допишите в `/opt/polovinka/.env` и выполните `docker compose up -d`.

**YandexGPT** — проще всего с российского сервера, оплата в рублях.

1. console.yandex.cloud → создайте каталог, привяжите платёжный аккаунт.
2. «Сервисные аккаунты» → создать, роль `ai.languageModels.user`.
3. В сервисном аккаунте → «Создать API-ключ».
4. ID каталога — на главной странице каталога.

```
AI_PROVIDER=yandex
YANDEX_API_KEY=ключ
YANDEX_FOLDER_ID=идентификатор-каталога
```

**Claude (Anthropic)** — качество текстов выше, но API не работает с российских
IP-адресов: нужен сервер в другой стране или прокси.

```
AI_PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-...
# если сервер в России — адрес вашего прокси к api.anthropic.com
ANTHROPIC_BASE_URL=
```

Модель по умолчанию — `claude-opus-5-5`, сменить можно в `AI_MODEL`.

Проверить: ответьте вдвоём на вопрос дня — под ответами появятся «Идеи для вас ✦»
(звёздочка значит, что идеи составил ИИ). Ошибки ИИ видны в
`docker compose logs app | grep ИИ`; при ошибке приложение молча возвращается
к заранее написанным идеям.


## Почта: вход по коду и обязательная привязка

Без SMTP приложение работает, но вход хранится только в телефоне: в настройках нет
пункта «Почта», а на экране входа — ссылки «Войти по почте». Код восстановления работает всегда.

Когда SMTP настроен, почта становится обязательной: после первого ответа человек видит
экран «Сохраните ваш аккаунт» и привязывает почту кодом из письма. Отложить на сутки можно,
только если письмо не дошло. В настройках почту можно сменить, но не отвязать.
Выключить обязательность: `EMAIL_REQUIRED=0` в `.env`.

Добавьте в `/opt/polovinka/.env` (пример для Mail.ru):

```
SMTP_HOST=smtp.mail.ru
SMTP_PORT=465
SMTP_USER=polovinka.online@mail.ru
SMTP_PASS=пароль-для-внешних-приложений
SMTP_FROM=polovinka.online@mail.ru
```

и перезапустите: `bash /opt/polovinka/deploy/install.sh` (или `cd /opt/polovinka && docker compose up -d`).

Где взять пароль:

- **Mail.ru** — id.mail.ru → «Безопасность» → «Пароли для внешних приложений» →
  «Добавить»; доступ — к почте (SMTP). Обычный пароль от ящика не подойдёт.
  `SMTP_FROM` должен совпадать с `SMTP_USER`, иначе Mail.ru отклонит письмо.
- **Яндекс** — id.yandex.ru → Безопасность → «Пароли приложений» → «Почта».
  Сервер `smtp.yandex.ru`, порт `465`.

Проверить, что письма уходят: `docker compose logs app | grep почта` — должно быть
«SMTP … готов». Если нет — пошаговая проверка (настройки, порты, пароль, тестовое письмо):

```
cd /opt/polovinka && docker compose exec app node server/dist/server/src/mailcheck.js ваш@адрес.ру
```

Если оба порта 465 и 587 закрыты — хостинг блокирует исходящую почту, откройте их через поддержку. Письмо содержит только шестизначный код, никаких рассылок.
Сколько людей уже привязали почту — на `/stats`, блок «Сохранность аккаунтов».
